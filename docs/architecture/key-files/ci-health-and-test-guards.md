# Key files: CI Health And Test Guards

[Subsystem index](../KEY_FILES.md). Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

The CI watchers and their issues, the CI support scripts, the contributor-audit and fix-wave tools, the guards that `bun run verify` runs, and the tests of those scripts.

## CI workflows

- `.github/workflows/full-ci.yml` — Full CI dispatch. On `pull_request` (`labeled`, `synchronize`, `reopened`) from a branch of this repository that carries the `full-ci` label, dispatches `test.yml` on the head branch with `gh workflow run`, so the pull request gets the full profile; it skips the dispatch when the branch moved after the event. Needs `actions: write`; a fork's branch never qualifies. Test: `test/scripts/full-ci-workflow.test.ts`.
- `.github/workflows/nightly-watch.yml` — Nightly watch. Runs on `workflow_run` completion of Test, Semgrep, OSV-Scanner and CI health on `main`, and on dispatch (`run_id`, `dry_run`). `resolve` admits scheduled runs and push-to-main runs of Test from this repository and prints the target workflow id and track; `watch` runs `scripts/nightly-issue.ts`, queued per repository, workflow and track and never cancelled. It checks out the default branch only (`scripts`, `.github/nightly-known-red.tsv`, `TODOS.md`), passes event fields through env, and holds `issues: write` plus read scopes. `test/scripts/nightly-issue.test.ts` requires every workflow with a schedule trigger to be listed.
- `.github/workflows/ci-health.yml` — CI health. Weekly (Monday 10:00 UTC) and on dispatch (`dry_run` defaults to true, `since`, `until`): runs `scripts/ci-health-report.ts` with full git history and the repository token (`issues: write`, `actions: read`, `checks: read`). Never cancelled in flight.
- `.github/workflows/semgrep.yml` — Semgrep. On pull requests, job `semgrep` fails only on findings new since the merge base (`--baseline-commit`); on the weekly schedule and dispatch, job `semgrep-full` scans the whole tree report-only and uploads SARIF to code scanning (the only job with `security-events: write`). The Semgrep image is pinned by digest; no secrets.
- `.github/workflows/osv-scanner.yml` — OSV-Scanner. Calls Google's reusable OSV workflow on pull requests that change `bun.lock` or `package.json`, weekly (Monday 06:30 UTC) and on dispatch; findings stay in the job log and a SARIF artifact (`upload-sarif: false`). Needs no secrets.
- `.github/workflows/actionlint.yml` — Actionlint. Lints the workflow YAML on push, pull request and dispatch, only when a file under `.github/workflows/` or `.github/actionlint.yaml` changes. `.github/actionlint.yaml` declares no self-hosted runner labels.
- `.github/workflows/fix-wave-gate.yml` — Fix-wave gate. On `pull_request_target` it runs `scripts/fix-wave-gate.ts` (job `contributor-gate`), which fails every pull request into `main` whose head repository is not this repository unless the `maintainer-override` label counts, and posts a welcome comment once when a pull request opens (`welcome-comment`). It checks out only the script and `.gstack/ship-policy.json` from the default branch and never runs pull-request code.
- `.github/workflows/fix-wave-closeout.yml` — Fix-wave closeout. On `pull_request_target` `closed`, when the pull request merged from a branch of this repository, runs `scripts/fix-wave-closeout.ts` (job `close-superseded`) to close the pull requests named on its `Supersedes #N` line. It checks out only that script and never runs pull-request code.

## Watchers and CI health

- `scripts/nightly-issue.ts` — nightly-watch's entry point: `bun scripts/nightly-issue.ts --run-id <id> [--repo <owner>/<name>] [--dry-run] [--resolve]`. Routes one run (`routeRun`): a scheduled run keeps one `Nightly red: <workflow>` issue (label `nightly-red`; open on red, update, reopen on a flap, close only on a later green run with complete evidence where every previously failing job passed); a push-to-main run of Test goes to `scripts/lib/master-red.ts`; anything else is refused with a next step. `.github/nightly-known-red.tsv` rows (at most 3, six tab-separated columns, each naming a `TODOS.md` entry) keep an incident open as `known-red`. `--resolve` prints the workflow id and track for the workflow's concurrency group. Exit 0 on any verdict, 1 when the run or the TSV cannot be read, 2 on usage. Test: `test/scripts/nightly-issue.test.ts`.
- `.github/nightly-known-red.tsv` — the known-red and known-skipped cells of scheduled runs: workflow, job, signature, kind, todo, review-by date. At most 3 rows; a row's `todo` must appear in `TODOS.md`. Race-hunt jobs cannot have rows and push runs never match them.
- `scripts/lib/master-red.ts` — master-red incidents for push-to-main runs of Test (`PUSH_ALLOWLIST`). Every watch evaluates all unevaluated completed push runs in run-number and attempt order above the high-water mark stored in the newest `master-red:json` block, folds each into the incident state (`applyRun`), computes the suspect range (last green SHA, first red SHA, merged PRs), and plans create, update, close or record-closed steps. A close without a merged repair PR opens up to 10 `flake` issues; `closeFlakes` closes a flake after its repair PR merged and a later complete run passed its file and arm; `externalPass` lets a scheduled Test run that contains the latest red commit clear an open issue. Writes re-read the issue first and retry up to 3 times; two watches creating the same issue leave one duplicate closed.
- `scripts/lib/ci-run.ts` — evidence for one completed workflow run, shared by the nightly-red and master-red paths. `collectEvidence` reads the run's jobs (50 per page), the failing jobs' check-run annotations, and the `ci-manifest` artifact for `test.yml`; a cancelled job counts as not run unless its annotation says it exceeded its timeout; a push run that reused a full run is judged by the run `reuse.json` names. It returns failing jobs, failing test identities, passed files and `complete` plus `problems`: a page, annotation or manifest that could not be read makes the evidence incomplete, and incomplete evidence never clears anything. `reproduceCommand` builds the one reproduce line (`bun run test:stress <file> --iterations 10`) from a validated test path; `exemptionRows` builds the stress-gate exemption records.
- `scripts/ci-manifest.ts` — `bun scripts/ci-manifest.ts --receipts-dir <dir> --out <file> [--summary <file>] [--deltas <tsv>]`. Reads every lane's executed-test receipts (JUnit reports) and writes the `gbrain-ci-manifest/v1` JSON bound to the workflow, event, SHA, run id and attempt: per-file executed, failed and skipped counts, and every failing test identity with its failure signature (omitted when the message carries a credential). `complete` is false for a killed shard, truncated report, older-attempt receipt, a lane that executed nothing without a declared skip row, or no receipts. `test.yml`'s `executed-receipts` job uploads it as `ci-manifest`; nightly-watch and `scripts/ci-full-suite-tree.sh` read it. Exit 0 when written, 2 on usage. Tests: `test/scripts/nightly-issue.test.ts` (`buildManifest`, `checkManifest`), `test/scripts/full-ci-workflow.test.ts`.
- `scripts/ci-health-report.ts` — `bun scripts/ci-health-report.ts [--days 1-31 | --since <date> [--until <date>]] [--responders a,b] [--repo <owner>/<name>] [--dry-run]`. Reads one window of `test.yml` runs through the REST API (runs, jobs, annotations, issues; never logs, fork runs or fork artifacts) and upserts one `ci-health` issue: first-attempt pass rates, exit criteria (push-to-main Test 95%, pull-request `test.yml` 90%; each met, missed or indeterminate), stress-gate failures and failure classes, master-red time to first response, the nightly-watch residual, the test files with the most failure annotations, shard spread with the `bun run weights:mine` command, new serial files, and nightly-watch's latest status. An explicit window with a missed target also opens a follow-up issue. Exit 0 on any report, 1 when the API cannot be read, 2 on usage. Test: `test/scripts/ci-health-report.test.ts`.
- `scripts/lib/gh-issue.ts` — Shared GitHub helpers: `inert()` neutralises run-derived text, `restClient()` calls the REST API with `GH_TOKEN` or `GITHUB_TOKEN` (else `gh api`) and retries a GET after a 5xx, plus issue and comment helpers, `redactCredentials` and `fetchArtifactJson` (one JSON file from a run artifact). Imported by `scripts/ci-reuse.ts`, `scripts/nightly-issue.ts`, `scripts/ci-health-report.ts`, `scripts/stress/gate.ts`, `scripts/lib/ci-run.ts` and `scripts/lib/master-red.ts`; `test/scripts/nightly-issue.test.ts` and `test/scripts/ci-reuse.test.ts` exercise it.

## CI scripts

- `scripts/test-gitleaks-config.sh` — proves `.gitleaks.toml` works before `test.yml`'s `gitleaks` job scans: in a temporary tree it plants the allowed fixture line under `.claude/skills/gstack/browse/test/` and expects gitleaks to pass, then appends a synthetic canary secret and expects gitleaks to exit 1. Needs the `gitleaks` CLI on `PATH`.
- `scripts/check-dynamic-ci.ts` — Parses each workflow under `.github/workflows` and checks the Trunk Dynamic CI wiring. A filter job (one with a `trunk-io/dynamic-ci` step) runs only on `pull_request`, with a SHA-pinned action, `secrets.TRUNK_API_TOKEN`, `continue-on-error: true`, a step timeout and `job-keys` equal to its outputs. A gated job's `if` starts with `!cancelled() && needs.<filter>.outputs.<key> != 'false'`; merge aggregates such as `full-suite` are never gated. Exit 1 lists problems. `bun run check:dynamic-ci`, in verify. Test: `test/scripts/check-dynamic-ci.test.ts`.
- `scripts/ci-bounded-run.ts` — Runs one setup command in its own process group and bounds each attempt by `--attempt-s`, by `--idle-s` of silence, or by a `--total-s` budget. A stalled or failed attempt is ended (SIGTERM, then SIGKILL after 10 s) and retried once after `--retry-s` (default 10); a second failure prints a named `::error::` and returns 1. Usage errors exit 2. `scripts/ci-bun-install.ts` imports it; `test/scripts/ci-bounded-run.test.ts` covers it.
- `scripts/ci-bun-install.ts` — Runs `bun install` with the flags you pass, through `runBounded`. `GBRAIN_CI_INSTALL_ATTEMPT_S` caps each attempt (default 180), `GBRAIN_CI_INSTALL_RETRY_SLEEP_S` sets the pause before the single retry (default 10), and `GBRAIN_CI_INSTALL_BUN` picks the Bun binary. Exits 1 after two failed attempts. Every install step in `test.yml` and `stress.yml` calls it; `test/scripts/ci-bun-install.test.ts` covers it.
- `scripts/ci-cheap-tier.sh` — Aggregator for the `cheap-tier` job of `test.yml` on pull requests. It reads the job results from `CHANGES`, `GITLEAKS`, `AUDIT`, `VERIFY`, `TYPECHECK` and `STRESS` and exits 1 unless each is `success`; a skipped stress job passes only when `DCI_STRESS` is exactly `false`. It always writes a "Full suite not run" step summary. `test/scripts/full-ci-workflow.test.ts` covers it.
- `scripts/ci-dependency-audit.sh` — Runs `bun audit` in the repository root for the `dependency-audit` job of `test.yml`. Found advisories, an unreachable registry (`audit_registry_unavailable`, retried with backoff) or an audit that failed without a report (`audit_incomplete`) exit 1 unless `BLOCKING=false`, which turns them into warnings. Other knobs: `REASON`, `AUDIT_DEADLINE_S` (420), `AUDIT_RETRY_DELAYS` ("15 45"), `AUDIT_ATTEMPT_TIMEOUT_S` (120). `test/scripts/ci-dependency-audit.test.ts` covers it.
- `scripts/ci-doc-checks.sh` — Runs the checks a doc-only change can still break: `bun run check:doc-history`, `check:docs-repo-paths`, `check:privacy` and `check:fixture-privacy`. Every check runs; the script exits 1 if any failed and prints a Fix line for each. `scripts/ci-local.sh --diff` calls it on a doc-only diff; `test/scripts/ci-local-rendering.test.ts` covers that call with a stub.
- `scripts/ci-executed-counts.ts` — Reads the per-lane test receipts from `--head-run` or `--head-dir` (optionally `--base-run` or `--base-dir`) and accounts for every executed test by lane, file, name and arm. Exit 1 on incomplete receipts, an empty lane, bad delta rows, or a base test missing from head that `docs/test-audit/2026-10-04/expected-deltas.tsv` (or `--deltas`) does not declare; 2 on usage errors; `--report-only` forces 0. The `executed-receipts` job of `test.yml` runs it report-only; `test/scripts/ci-executed-counts.test.ts` covers it.
- `scripts/ci-full-suite-tree.sh` — Writes `$ARTIFACT_DIR/tree.json` for the `full-suite` job of `test.yml`: tested git tree, commit, workflow, event, run id and attempt, profile `full`, plus the executed test files and count when `MANIFEST` (a `ci-manifest.json`) is complete and matches this run and commit; otherwise it warns and omits both. Needs `ARTIFACT_DIR`, `RUN_ID`, `RUN_ATTEMPT`, `WORKFLOW`, `EVENT`. `scripts/ci-reuse.ts` reads the artifact; `test/scripts/full-ci-workflow.test.ts` covers it.
- `scripts/ci-local-e2e-smoke.sh` — Smoke-tests `scripts/run-e2e.sh --dry-run-list`: the no-argument list must equal the end-to-end test files minus the names in `scripts/e2e-live-key-only.txt` (0 when that directory is absent), one named file must echo back, and shards 1/4 to 4/4 must sum to the same total. Exits 1 with a `[ci-local] ERROR` line on a mismatch. `scripts/ci-local.sh` runs it; no test file names it.
- `scripts/ci-local.sh` — Local copy of the CI gate (`bun run ci:local`; `ci:local:diff` adds `--diff`). It runs the gitleaks checks, the run-e2e smoke test, the timeout guard, `bun run verify`, the serial and slow lanes, then unit and end-to-end files in four parallel shards logged in `.context/ci-local-shards/`. `--no-shard` skips sharding; `--diff` on a doc-only diff runs only gitleaks and `scripts/ci-doc-checks.sh`. Non-zero exit on any failure or missing gitleaks. `test/scripts/ci-local-rendering.test.ts` covers it.
- `scripts/ci-manifest-diff.sh` — Classifies manifest changes by parsed JSON (`jq`), failing closed on unreadable files. `version-only` and `dependency-change` compare two JSON files and print `true` or `false`; `drop-version-only` filters a changed-file list on stdin; `dependency-scope` prints `blocking=` and `reason=` for the `dependency-audit` job of `test.yml`. Fetches revisions with `gh api` using `REPO`, `BASE_SHA`, `HEAD_SHA`; exits 2 on usage. `test/scripts/ci-manifest-diff.test.ts` covers it.
- `scripts/ci-typecheck.sh` — Wraps a typecheck command (`bash scripts/ci-typecheck.sh bun run typecheck` in `test.yml`) under `timeout` (`GBRAIN_TYPECHECK_ATTEMPT_SECONDS`, default 360). If the command ends by abort or signal (status above 128), it deletes `node_modules/.cache/gbrain-typecheck.tsbuildinfo` and runs it once more; any other status, including a type error or a timeout (124), is the step's exit code. Writes `state_written=true|false` to `$GITHUB_OUTPUT`. `test/scripts/ci-typecheck.test.ts` covers it.
- `scripts/ci-reuse.ts` — Decides whether a push to main can reuse a passed full-suite run of the identical git tree (`--workflow test --sha --repo --output`, optional `--summary`, `--record`). It reuses only for a two-parent merge with a same-repository dispatch or push run whose `full-suite` job succeeded and whose `full-suite-tree` artifact matches; any API error or mismatch gives `reuse=false` and a reason. Exit 0 whenever it decided, 2 on usage. The `changes` job of `test.yml` runs it; `test/scripts/ci-reuse.test.ts` covers it.

## Contributor audit, fix wave and security scan

- `scripts/wave-security-scan.sh` — On-demand scan of the lines a git range adds (`<base>..<head>`, two refs, or `origin/main..HEAD`; `--json` for a machine summary). Obfuscation or `eval` in code is an alarm; new URLs, spawn calls, env reads and `package.json` or `bun.lock` changes are informational. It also runs gitleaks over the range with default rules only. Exit 1 on an alarm, a leak or a gitleaks lane that did not run; 2 for a bad range or missing python3. `bun run wave-security-scan`. Test: `test/wave-security-scan.test.ts`.
- `scripts/contributor-audit.ts` — `bun run audit:contributors <base>..<head> [--prs <manifest>]` takes each first-parent merge in the range, and each listed PR head trial-merged, runs its tests, reverses its non-test hunks, re-runs the tests and restores the tree. Each case is `discriminates`, `does_not_discriminate`, `vacuous_failure`, `setup_failed`, `conflict` or `not_audited`; `scripts/wave-security-scan.sh` runs once. Exit 0 clean, 1 needs review, 2 usage, 130 interrupted (`--resume`). `test/scripts/contributor-audit.test.ts` covers it.
- `scripts/contributor-audit-fixture.ts` — `bun scripts/contributor-audit-fixture.ts <empty-dir>` builds a small offline git repository with six merges and one conflicting open PR head (plus `prs.json`), one case for each result the audit must tell apart, and prints the audit command for it. `test/scripts/contributor-audit.test.ts` imports `buildFixture` to run the audit on it.
- `scripts/fix-wave-closeout.ts` — Decision script of the `fix-wave-closeout` workflow. When a same-repository pull request merges into main, it closes each open PR named on a `Supersedes` line of the merged PR's body with a thank-you comment (marked, so a rerun does not comment twice; at most 50 per run). `--dry-run` only lists; the payload comes from `--event` or `GITHUB_EVENT_PATH`. Exit 1 without a payload or `GITHUB_REPOSITORY`, otherwise 0. `test/scripts/fix-wave-closeout.test.ts` covers it.
- `scripts/fix-wave-gate.ts` — Decision script of the `fix-wave-gate` workflow. A pull request into main passes when its head repository is `GITHUB_REPOSITORY`, or when the latest `maintainer-override` label event came from a human listed under `maintainers` in `.gstack/ship-policy.json`; anything else exits 1. `--comment` posts a welcome comment once on a failing PR and exits 0. The payload comes from `--event` or `GITHUB_EVENT_PATH`. `test/scripts/fix-wave-gate.test.ts` covers it.

## Test and repository guards

- `scripts/check-bash32.sh` — Runs `bash -n` over every tracked `*.sh` (guard fixtures excluded) with a real bash 3.2 parser: the `GBRAIN_BASH32` binary, `/bin/bash` when it is 3.x, else the digest-pinned `bash:3.2` Docker image. Exit 1 on a parse error, 2 on a bad `GBRAIN_BASH32`, 0 on a pass or on a skip when no parser exists; `GBRAIN_TEST_BASH32_REQUIRE=1` makes that skip exit 2. Run by the verify job in `.github/workflows/test.yml` as `bun run check:bash32`, not by `bun run verify`. Test: `test/scripts/check-bash32.test.ts`.
- `scripts/check-bun-test-timeout.sh` — Greps `.github/workflows` and `scripts` for `bun test` commands with no `--timeout` (comment lines and lines naming this script are skipped) and exits 1 with the offending lines, else 0. A bare `bun test` leaves setup hooks on bun's default 5 s budget. Run directly by the verify job in `.github/workflows/test.yml` and by `scripts/ci-local.sh`, not through `bun run verify`. It has no test file of its own.
- `scripts/check-changelog-headings.ts` — Compares the `## [` release headings in the working `CHANGELOG.md` (a missing file counts as none) with those in the base ref's copy (`GBRAIN_CHANGELOG_BASE_REF`, default `origin/main`). Exit 1 when the working file lacks a base heading; an unreadable base ref exits 1 under `CI=true` and skips otherwise, and a base with no release heading skips. `bun run check:changelog-headings`, in verify. Test: `test/scripts/check-changelog-headings.test.ts`.
- `scripts/check-file-url-pathname.sh` — Greps `.ts`, `.mts`, `.js` and `.mjs` files under `test/` (guard fixtures excluded) for `import.meta.url).pathname`, `import.meta.url.pathname` and `pathToFileURL(...).pathname`, which keep `%20` escapes and break under a checkout path with a space. Exit 1 prints the hits; use `fileURLToPath` or `import.meta.dir` instead. Skips when no such file exists. `bun run check:file-url-pathname`, in verify; `GBRAIN_GUARD_ROOT` sets a fixture root. Skip case tested in `test/scripts/check-empty-subject-skips.test.ts`.
- `scripts/check-fixture-privacy.sh` — Case-insensitive grep of fixture, eval-corpus and audit-evidence paths for banned real-name tokens (private agent, company, fund and person names); audit and eval paths get the real-entity subset only. In this tree `docs/test-audit` is the scanned path that exists. Exit 1 names each token and file; exit 0 with `GBRAIN_CHECK_SKIPPED` when no scanned path holds a file. `bun run check:fixture-privacy`, in verify; `GBRAIN_GUARD_ROOT` sets a fixture root. Skip case tested in `test/scripts/check-empty-subject-skips.test.ts`.
- `scripts/check-function-size.ts` — Function-length ratchet. It measures every function-like node in the `.ts` files of the src directory (not `*.generated.ts` or `.d.ts`) with the TypeScript compiler API. Exit 1 on a function over 300 lines with no baseline row, growth past its row, a row that can be lowered or removed, a row whose function is missing, or a raised or added row without an issue/TODO id. `--seed` and `--transfer [--from <ref>]` rewrite the baseline. Env: `GBRAIN_FUNCTION_SIZE_LIMIT`, `_SLACK`, `_BASE_REF`, `GBRAIN_GUARD_ROOT`. Skips while the src directory and baseline are empty. `bun run check:function-size`, in verify. Test: `test/scripts/check-function-size.test.ts`.
- `scripts/check-key-files-current-state.sh` — Keeps the reference docs history-free and small. Exit 1 on a bolded release-version marker in `docs/architecture/KEY_FILES.md`, `docs/architecture/key-files/*.md` or `docs/TESTING.md`; on a size over the cap (`CLAUDE.md` 35000 bytes, `GBRAIN_CLAUDE_MD_MAX_BYTES`; `docs/TESTING.md` 120000, `GBRAIN_TESTING_MD_MAX_BYTES`; index 10000; each key-files page 60000); and on two bullets for one source file. History phrases only warn. `GBRAIN_DOC_GUARD_ROOT` sets the root. `bun run check:doc-history`, in verify. Test: `test/scripts/check-key-files-current-state.test.ts`.
- `scripts/check-module-size.sh` — File-length ratchet. Each row of `scripts/module-size-limits.tsv` is a `wc -l` ceiling; exit 1 when a file exceeds it, sits more than 50 lines under it, or is missing, and when an unlisted `.ts` file under the src directory (not `*.generated.ts` or `*.test.ts`) passes 1500 lines. Env: `GBRAIN_MODULE_SIZE_SLACK`, `GBRAIN_MODULE_SIZE_NEWFILE_CAP`, `GBRAIN_GUARD_ROOT`. Skips while the src directory and TSV are empty. `bun run check:module-size`, in verify. Test: `test/scripts/check-module-size.test.ts`.
- `scripts/check-no-tracked-symlinks.sh` — Lists `git ls-files -s` entries with mode 120000 and exits 1, printing each link and its target, unless the path is in the script's `ALLOWLIST` (empty). Exit 0 when none, or with a `GBRAIN_CHECK_SKIPPED` line when git lists no tracked file. `bun run check:no-tracked-symlinks`, in verify. Test: `test/no-tracked-symlinks-guard.test.ts`.
- `scripts/check-orphan-modules.mjs` — Reachability walk over relative static, dynamic and `require` imports, from the `ENTRYPOINTS` list, `package.json` `exports` targets, `test/` and `scripts/`. Exit 1 on a module in the src directory that no entrypoint or test reaches, a test-only module without a reasoned `PERMITTED_TEST_ONLY` entry, or an invalid or stale entry; exit 2 on an infra error. All three lists are empty, so it skips while the src directory is empty. `bun run check:orphan-modules`, in verify. Test: `test/scripts/check-orphan-modules.test.ts`.
- `scripts/check-privacy.sh` — Exit 1 when a tracked text file (or, with `--staged`, a staged one) contains the banned private-fork name (case-insensitive) or one of two banned filesystem path prefixes. The script, `scripts/check-fixture-privacy.sh`, `scripts/check-test-real-names.sh`, `scripts/check-proposal-pii.sh`, `CLAUDE.md` and `test/scripts/check-proposal-pii.test.ts` are allowed; `CHANGELOG.md` is checked for the name only. Exit 2 when git is missing or an argument is unknown; skips when no file is listed. `bun run check:privacy`, in verify. Test: `test/privacy-script-wired.test.ts`.
- `scripts/check-proposal-pii.sh` — Greps `docs/proposals/*.md` (working tree, or staged files with `--staged`) for a fixed, case-insensitive list of phrases: a private repository reference, personal-relationship and funeral phrases, and the private fork name. Exit 1 prints each file and pattern, 2 is a setup error, and it skips while `docs/proposals` is absent or holds no `.md` file. `bun run check:proposal-pii`, in verify. Test: `test/scripts/check-proposal-pii.test.ts`.
- `scripts/check-retired-phrases.sh` — Greps `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md`, `docs`, `scripts`, `.github` and `package.json` for the stale phrases in its table: contributor-workflow sentences naming code that is not here, paths into the src tree, the embedded database engine, brain table names and product CLI command words. Directories of historical records such as `docs/test-audit` are exempt. A hit prints FAIL, Why, Fix and See; exit 1. `bun run check:retired-phrases`, in verify; `GBRAIN_GUARD_ROOT` sets a fixture root. Test: `test/scripts/check-retired-phrases.test.ts`.
- `scripts/check-structural-manifest.sh` — Runs `bun scripts/classify-tests.ts --check`, which exits 1 when `scripts/structural-suites.tsv` differs from a fresh classification of the test suites. Regenerate with `bun scripts/classify-tests.ts`. `bun run check:structural-manifest`, in verify. It has no test of its own; the classifier is tested in `test/scripts/classify-tests.test.ts`.
- `scripts/check-test-discriminates.sh` — Manual helper, not wired into verify or CI: `bash scripts/check-test-discriminates.sh <test-file> <source-file>...`. It copies the source files aside, reverts them to HEAD (dirty) or to the base ref (clean; `DISCRIMINATE_BASE`, default merge-base with `origin/master`, else `HEAD~1`), runs `bun test --timeout=60000` on the test, then restores them. Exit 0 the test fails without the fix, 1 it still passes, 3 a crash with no failing test, 2 bad usage. Prints the line for the PR template's "Discrimination test" field.
- `scripts/check-test-env-opt-ins.ts` — Parses `.ts` files under `test/` with the TypeScript AST and fails (exit 1) when a test gates execution (`skipIf`, `if`, early return) on a `GBRAIN_*` variable that the operator-env preload strips, unless the file sets that variable itself. The strip policy comes from `test/helpers/operator-env-policy.ts`. Skips when there is no TypeScript file to scan. `bun run check:test-env-opt-ins`, in verify; `GBRAIN_GUARD_ROOT` sets a fixture root. Test: `test/scripts/test-env-opt-ins-guard.test.ts`.
- `scripts/check-test-isolation.allowlist` — Baseline allow-list for `scripts/check-test-isolation.sh`: one test path per line, `#` lines ignored. It holds two entries, `test/scripts/check-test-isolation.test.ts` and `test/helpers/with-env.test.ts`. A listed file is skipped by every rule; the list may only shrink, so a violation is fixed or the file is moved to `*.serial.test.ts` instead.
- `scripts/check-test-isolation.sh` — Lints non-serial `*.test.ts` files under `test/` and exits 1 on R1 `process.env` mutation, R2 `mock.module(` and R8 scratch directories joined onto the test's own directory. It skips `*.serial.test.ts` and files in `scripts/check-test-isolation.allowlist`. `--as-parallel FILE...` lints named files as if they ran in the parallel pool (exit 2 with no file). `bun run check:test-isolation`, in verify. Tests: `test/scripts/check-test-isolation.test.ts`, `test/scripts/check-test-isolation-r8.test.ts`.
- `scripts/check-test-placeholders.d.mts` — TypeScript declarations for the two exports of `scripts/check-test-placeholders.mjs`, `scanTree` and `evaluate`, with the `PlaceholderSite` and `AllowlistEntry` shapes. `test/scripts/check-test-placeholders.test.ts` imports both functions from the `.mjs` file, so these types cover that import under `bun run typecheck`.
- `scripts/check-test-placeholders.mjs` — Walks `test/**/*.test.ts` (not `test/fixtures`) with the TypeScript AST and flags the no-op assertions `expect(true)`, `expect(true).toBe(true)`, `expect(true).toBeTruthy()` and `expect(1).toBe(1)`. The in-script allowlist is empty; a stale entry also fails. Exit 1 on a hit, 2 when `test/` is missing, skip when there is no test file. `bun run check:test-placeholders`, in verify; run by `node`; argv or `GBRAIN_GUARD_ROOT` sets a fixture root. Test: `test/scripts/check-test-placeholders.test.ts`.
- `scripts/check-test-real-names.sh` — Greps TypeScript files under `test/` for a fixed list of banned real-name strings (whole word, case-insensitive) and one banned email address, using `rg` when installed and `grep` otherwise. Exact `file:string` pairs in the script's `ALLOWLIST` are exempt. Exit 1 lists the hits, 2 when neither tool exists; a tree with no TypeScript file prints `GBRAIN_CHECK_SKIPPED`. `bun run check:test-names`, in verify. The skip case is tested in `test/scripts/check-empty-subject-skips.test.ts`.
- `scripts/check-trailing-newline.sh` — Fails (exit 1) and lists tracked non-empty text files that do not end in a newline: `.ts`, `.js`, `.json` and `.md` files in subdirectories of `test/` and of the src directory (plus `.sql` there), and every tracked `.md` file. Guard fixtures are skipped; with `GBRAIN_GUARD_ROOT` it scans a fixture tree with `find`. Prints `GBRAIN_CHECK_SKIPPED` when no file is in scope. `bun run check:newlines`, in verify. The skip case is tested in `test/scripts/check-empty-subject-skips.test.ts`.
- `scripts/check-weight-coverage.ts` — Checks the shard weight maps `scripts/test-weights.json` (unit), `scripts/serial-weights.json` and `scripts/e2e-weights.json`. An entry naming a missing file exits 1. A lane whose unweighted share passes its bound (unit 5%, serial and e2e 10%) warns and prints the `bun run weights:mine` command, and fails only when `GITHUB_EVENT_NAME=schedule`. Skips when no lane has a test file. `bun run check:weight-coverage`, in verify; `GBRAIN_GUARD_ROOT` sets a fixture root. Test: `test/scripts/check-weight-coverage.test.ts`.
- `scripts/function-size-baseline.tsv` — Baseline for `scripts/check-function-size.ts`: tab-separated rows `path`, `name`, `lines`, `justification`, one per function over 300 lines, sorted by path then name. It holds only the header and comment lines, so any over-limit function is a new failure. Rows may only shrink; raising or adding one needs an issue/TODO id in the justification, which the guard checks against the base ref's copy.
- `scripts/module-size-limits.tsv` — Ceiling table for `scripts/check-module-size.sh`: tab-separated rows `path`, `max_lines`, `policy` (only `ratchet`) and `note`. It holds only comment lines. Adding a row freezes a file at a `wc -l` ceiling; raising a ceiling is a reviewer-visible edit, and a ceiling more than 50 lines above the file's length fails.
- `scripts/guard-self-test.sh` — Proves each scanner guard can fail. For every `selftest yes` row in `scripts/guards-manifest.tsv` it runs the guard through `GBRAIN_GUARD_ROOT` against `test/fixtures/guards/<guard>/bad` and every `bad-*` sibling (each must exit non-zero) and `good` (must exit 0). It also fails when a `scripts/check-*` file has no manifest row or the pass takes over 30 s. `GUARD_SELF_TEST_JOBS` (default 4) sets parallelism. Runs as the solo check `check:guard-self-test` in verify. It has no test file of its own.
- `scripts/guards-manifest.tsv` — Registry of the `scripts/check-*` guards: tab-separated `guard`, `class` (scanner, buildfresh or repostate), `selftest` (yes, todo or exempt) and `notes`. `scripts/guard-self-test.sh` runs the `selftest yes` rows and fails on a guard file with no row; `test/scripts/run-verify-parallel.test.ts` requires every row's guard to run from verify or be exempted there. A new guard needs a row here.
- `scripts/lib/guard-candidates.sh` — Defines the bash function `guard_candidates`. It reads file names on stdin, keeps existing regular files, runs `grep -l` with the caller's pattern arguments over batches of 128, and prints the matching files. A grep exit other than 0 or 1 is returned, so a failed batch is an error. Sourced by `scripts/check-privacy.sh` and `scripts/check-test-isolation.sh`; its batching is tested in `test/privacy-script-wired.test.ts`.
- `scripts/verify-move-only.ts` — Checks that a commit range only moves code. For each touched `.ts` or `.js` file it compares top-level statements on the base and head sides token for token (`scripts/lib/normalize-tokens.ts`), ignoring comments, whitespace, imports, re-exports and `export`/`default` modifiers; `--rename-map <json>` rewrites base identifiers first. Run as `bun scripts/verify-move-only.ts [<base>..<head> | <commit>]` (default `HEAD~1..HEAD`). Exit 1 on a changed statement or non-source file, 2 on bad arguments. Not in `package.json` or a workflow. Test: `test/scripts/verify-move-only.test.ts`.
- `scripts/scan-worktree-secrets.sh` — Copies every tracked file plus every untracked file git does not ignore into a temp directory and runs `gitleaks dir` there with `.gitleaks.toml` and `--redact`. Tracked files are always included, even if a `.gitignore` rule would hide them. Needs `python3` and `gitleaks`; a gitleaks finding gives a non-zero exit. Called by `scripts/ci-local.sh` (`bun run ci:local`, `bun run ci:local:diff`); `test/scripts/ci-local-rendering.test.ts` only stubs it.
