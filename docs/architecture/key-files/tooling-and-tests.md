# Key files: Tooling And Tests

[Subsystem index](../KEY_FILES.md). Read only the entries relevant to your change.
Current behavior and load-bearing invariants; history belongs in Git and CHANGELOG.

The test lanes and what runs them: the Test and Stress workflows, the lane runner scripts, shard weights, the stress harness, coverage gates, test helpers and preloads, and the tests of that tooling.

## Test workflows

- `.github/workflows/test.yml` — Test, the main CI workflow. Triggers: push and pull request on `main`, `merge_group` (inert until a merge queue is enabled), a nightly schedule and `workflow_dispatch`, whose `stress_files`, `stress_base` and `stress_head` inputs run only the stress gate as a diagnostic. Every event except a diagnostic dispatch runs `changes` (the master-push reuse decision), `gitleaks`, `dependency-audit`, `verify`, `typecheck`, `stress-changed-tests` (calls `stress.yml`) and `executed-receipts` (receipts ledger and the `ci-manifest` artifact). A pull request adds the `dynamic-ci` filter and the `cheap-tier (full suite not run)` aggregate. Every other event adds the full profile: `serial-tests` (4 shards), `e2e` (`scripts/run-e2e.sh`), `test` (4 unit shards, two per runner), `coverage-report` (advisory), the aggregates `test-status` and `full-suite` (which uploads `full-suite-tree`), and, on a reusing push, `reused-full-suite`. Concurrency is keyed per pull request or push commit. Every action is pinned to a commit SHA. Event rules: [CI event parity](../../ci-event-parity.md); guards: `test/scripts/ci-pr-scope.test.ts`, `test/scripts/full-ci-workflow.test.ts`, `test/scripts/ci-gates.test.ts`.
- `.github/workflows/stress.yml` — Stress, a reusable workflow (`workflow_call`) that `test.yml` calls once as `stress-changed-tests` with `mode: gate`. `plan` runs `scripts/stress/gate.ts plan`: on `pull_request` and `merge_group` it selects every added or modified test file plus direct importers of changed `test/helpers/` files; a stress dispatch runs the files it names; any other event gets "not a PR event". `shards` runs the planned iterations with `bun run test:stress` (at most 12 shards at once, each exits 0 on test failures). `result` runs `gate.ts report` and alone decides: a failure that matches an open exemption record passes as known, any other failure, a missing receipt or a failed plan fails.

## Lane runners, sharding, weights and generated artifacts

- `scripts/run-e2e.sh` — Runs each `test/e2e/*.test.ts` file in its own `bun test` process, one after another, with a temp `HOME` and `GBRAIN_HOME`, a scrubbed `GBRAIN_*` env and a per-file cap (`GBRAIN_E2E_FILE_TIMEOUT`, 180 s). `SHARD=N/M` takes a weighted slice via `e2e-weights.json`. Exits 1 on a failed file, 2 on a bad `SHARD` or a changed real user config, 0 with no e2e files. Run by `bun run test:e2e` and the `e2e` job of `test.yml`; test: `test/scripts/e2e-runner.test.ts`.
- `scripts/run-heavy.sh` — Runs every `*.sh` file in `tests/heavy/` one after another (names starting with `_` are skipped; an optional glob argument filters by basename), keeps going after a failure and lists each failure with a rerun command. Exits with the first failure's code, 1 if a pattern matches nothing, 0 with no scripts; that directory is absent here, so it does nothing. Run by `bun run test:heavy`; test: `test/scripts/run-heavy.test.ts`.
- `scripts/run-serial-tests.sh` — Runs each `*.serial.test.ts` file in its own `bun test --max-concurrency=1` process, through a pool (`GBRAIN_SERIAL_POOL`, up to 4) with a per-file kill (`GBRAIN_SERIAL_FILE_TIMEOUT`, 300 s); a file killed from outside gets one rerun. `SHARD=N/M` uses `serial-weights.json`. Exits 1 on a failed file, 2 on a bad `SHARD`. Run by `bun run test:serial`, `run-unit-parallel.sh` and the `serial-tests` job; test: `test/scripts/run-serial-pool.test.ts`.
- `scripts/run-slow-tests.sh` — Runs every `*.slow.test.ts` file outside `test/e2e` in one `bun test --timeout=120000` call, with database URLs and `GBRAIN_HOME` unset; file arguments replace discovery and `--dry-run-list` prints the set. Exits with the `bun test` code, or 0 when there are none. Run by `bun run test:slow`, `test:full` and `ci-local.sh`; CI unit shards run slow files through `test-shard.sh` instead. No test file targets it directly.
- `scripts/run-unit-parallel.sh` — The local fast test loop: starts one `run-unit-shard.sh` per CPU at once (at most 4 unless `--shards` or `SHARDS` is set), trims concurrency to free memory, caps each shard (`GBRAIN_TEST_SHARD_TIMEOUT`, 3000 s), then runs `run-serial-tests.sh` if serial files exist. Files that failed on out-of-memory or an outside kill get one serial rerun. Exits 1 on failure, 2 on usage errors. Run by `bun run test`; test: `test/scripts/run-unit-parallel.test.ts`.
- `scripts/run-unit-shard.sh` — Runs one slice of the unit suite: every `*.test.ts` outside `test/e2e`, `*.slow.test.ts` and `*.serial.test.ts`, split by weight through `sharding.ts` when `SHARD=N/M` is set. One `bun test` per file; an incomplete summary or file count fails. Knobs: `--max-concurrency`, `GBRAIN_TEST_TIMEOUT_MULTIPLIER`. Exits 1 on failure, 2 on an unknown flag. Called by `run-unit-parallel.sh` and `ci-local.sh`; test: `test/scripts/run-unit-shard.test.ts`.
- `scripts/run-verify-parallel.sh` — Runs the `CHECKS` array (typecheck and `check:*` guards) through a bounded pool, then `check:guard-self-test` alone. Per-check cap `GBRAIN_VERIFY_TIMEOUT` (120 s); `GBRAIN_VERIFY_SKIP_TYPECHECK=1` drops typecheck. A check that prints `GBRAIN_CHECK_SKIPPED: <reason>` counts as skipped. Exits 1 on any failure, 2 on usage errors. Run by `bun run verify` and the `verify` job of `test.yml`; test: `test/scripts/run-verify-parallel.test.ts`.
- `scripts/run-with-receipt.sh` — Wraps one `bun test` call (`<lane> <tag> -- bun [--no-env-file] test --timeout=N ... <files>`) so it records an executed-test receipt when `GBRAIN_TEST_RECEIPT_DIR` is set; otherwise the command runs unchanged. Exits 2 on a wrong argument shape, a missing `--timeout` or no `*.test.ts` argument, else with the command's code. Used by the `verify` job of `test.yml`; test: `test/scripts/run-with-receipt.test.ts`.
- `scripts/test-shard.sh` — Runs shard `<index> <total>` of the CI unit suite: every `*.test.ts` under `test/` except `*.serial.test.ts` and `test/e2e` (slow files included), split by weight through `sharding.ts` and run in one `bun test --timeout=60000` call. `--dry-run-list` prints the shard's files. Exits 1 on bad arguments, else with the `bun test` code. Run through `test-shard-pack.sh` by the `test` job; test: `test/scripts/test-shard.slow.test.ts`.
- `scripts/test-shard-pack.sh` — `<total-shards> <shard-index>...`: runs several unit shards of one partition at once on one runner. Each shard runs `test-shard.sh` under `capture-test-log.ts`, with its own coverage, receipts, timing log, console and exit files under `GBRAIN_SHARD_PACK_DIR/<shard>/` (required). Exits 2 on bad usage, else 0 only if every shard passed. Run by the `test` job of `test.yml`; test: `test/scripts/test-shard-pack.test.ts`.
- `scripts/sharding.ts` — Reads test paths on stdin and prints shard K of N, packing greedily longest-first over per-file weights (default `scripts/test-weights.json`, p75 for files without one). Options: `--weights <path>`, `--fallback-on-error` (flat weights on a bad map), `--sum` (predicted weight of a list). Exits 1 on bad weights, 2 on usage errors. Called by `run-unit-shard.sh`, `run-serial-tests.sh`, `run-e2e.sh`, `test-shard.sh`; test: `test/scripts/sharding.test.ts`.
- `scripts/select-e2e.ts` — Lists the changed files (against `origin/main`, working tree and untracked) and prints the `test/e2e/*.test.ts` files to run: all of them, or none when every change is a doc path (`docs/`, root `*.md`, `LICENSE`, `VERSION`). `--classify-only` prints `EMPTY`, `DOC_ONLY` or `SRC` instead. Exits 2 when git fails. Run by `bun run ci:select-e2e`, `ci-local.sh` and `coverage-diff-gate.ts`; test: `test/select-e2e.test.ts`.
- `scripts/classify-tests.ts` — Scans `test/**/*.test.ts` for suites whose assertions read repo source or doc text (`readFileSync`, `Bun.file`, or grep-style exec calls on repo paths) and writes them to `structural-suites.tsv`. `--check` exits 1 when the committed TSV differs from a fresh scan; `--summary` prints counts only. Run by `check-structural-manifest.sh` (in `verify`) and `regen-all.ts`; test: `test/scripts/classify-tests.test.ts`.
- `scripts/serial-files.tsv` — Manifest of `*.serial.test.ts` files with columns `path`, `class`, `reason`, one row per file; it has no rows because none exists here. `test/scripts/serial-files.test.ts` checks it through `scripts/lib/serial-manifest.ts`, so adding or removing a serial file means adding or deleting its row.
- `scripts/serial-weights.json`, `scripts/serial-weights.metadata.json` — Seconds per serial test file, read by `run-serial-tests.sh`, `check-weight-coverage.ts` and `stress/plan.ts`; the map is `{}` because no serial test file exists. The metadata (lane, unit, source runs, file counts) comes from `mine-shard-weights.ts`; its test checks `totalFiles` against the map.
- `scripts/test-weights.json`, `scripts/test-weights.metadata.json` — Milliseconds per unit test file, one `test/...` key each. `sharding.ts` reads it, so it decides which shard runs a file; `check-weight-coverage.ts` and `stress/plan.ts` read it too, and a file with no entry gets the p75 weight. `bun run weights:mine` rewrites both files.
- `scripts/e2e-weights.json`, `scripts/e2e-weights.metadata.json` — Milliseconds per e2e test file, read by `run-e2e.sh` for `SHARD=N/M`, `check-weight-coverage.ts` and `stress/plan.ts`; the map is `{}` because no e2e file exists here. The metadata (lane, unit, source run, job list, zero file counts) comes from `mine-shard-weights.ts`.
- `scripts/e2e-live-key-only.txt` — Test paths, one per line with `#` comments, for e2e files that need provider keys no CI job supplies; it holds only comments. `run-e2e.sh` leaves listed files out of its default run, `ci-local-e2e-smoke.sh` reads it, and `stress/run.ts` and `stress/gate.ts` report listed files as not stressed.
- `scripts/structural-suites.tsv` — Generated list of test suites whose assertions read repo source or doc text (columns `file`, `suite`, `cases`, `detector`). Only `classify-tests.ts` writes it; `check-structural-manifest.sh` and `regen-all.ts --check` fail when it is stale, and `render-coverage-summary.ts` reads it. Do not edit rows by hand.
- `scripts/lib/serial-manifest.ts` — Pure checker for `serial-files.tsv`: `checkSerialManifest` returns one message per problem. It flags a serial test file with no row, a row for a missing file, an unknown class, a boilerplate or short reason, an `R1` row whose file no longer sets `process.env`, an `R2` row without `mock.module`, and an `exclusive` row that disagrees with `EXCLUSIVE_FILES`. Used by `test/scripts/serial-files.test.ts`.
- `scripts/lib/test-env.sh` — Shell helpers the test runner scripts source: `detect_cpus`, `detect_available_mem_mb`, `AGENT=0`, a default `GBRAIN_TEST_WAIT_MULTIPLIER=2` when `COVERAGE_DIR` is set, and the receipt functions (`receipts_init`, `receipt_begin`, `receipt_end`, `receipt_empty`) that write receipt, file-list and JUnit files into `GBRAIN_TEST_RECEIPT_DIR`. No test targets it alone; `test/scripts/run-with-receipt.test.ts` exercises it.
- `scripts/lib/normalize-tokens.ts` — Turns TypeScript source into a token list with whitespace, comments and JSDoc dropped and strings and templates kept byte for byte, with an optional identifier rename map; exports `normalizeTokens`, `normalizeSource` and `normalizeNode`. Imported by `scripts/verify-move-only.ts`; test: `test/scripts/normalize-tokens.test.ts`.
- `scripts/mine-shard-weights.ts` — Builds the shard weight maps from timing logs of passing `test.yml` runs (`gh run view`, `gh run download`) or from a log file or stdin, for `--lane unit|serial|e2e`; several `--run` values give per-file medians. It refuses failed, incomplete or empty logs, drops files git no longer tracks, and writes the lane's weights and metadata files (`--out` overrides). Run as `bun run weights:mine`; test: `test/scripts/mine-shard-weights.test.ts`.
- `scripts/profile-tests.sh` — Reads captured `bun test` output on stdin, takes lines ending in a `[12ms]` or `[1.2s]` time and prints the slowest as milliseconds (`-n N`, default 10). Run by `bun run test:profile`; no test covers it.
- `scripts/capture-test-log.ts` — `--job <name> --out <file> -- <command>`: runs the command, mirrors its output unchanged and writes each line to the log with the job name, a `capture` tag and an ISO time, between start and `exit=N` marker lines that `mine-shard-weights.ts` reads. On failure it adds failing tests and reproduce commands to `GITHUB_STEP_SUMMARY`. Exits with the command's code, 2 on bad usage. Run by `test-shard-pack.sh`; test: `test/scripts/capture-test-log.test.ts`.
- `scripts/eval-spend-guard.sh` — `<cap_usd> <estimate_usd> -- <command...>`: refuses a paid command when the JSONL ledger (`GBRAIN_EVAL_SPEND_LEDGER`; must exist unless `GBRAIN_EVAL_SPEND_LEDGER_INIT=1`) plus the estimate would pass the cap. It writes a reservation row before the run and a reconciliation row after, and fails closed on a bad ledger. Exits with the command's code, 2 on usage errors, 3 on refusal. No workflow or script calls it; test: `test/eval-spend-guard.test.ts`.
- `scripts/ship-remote-tests.sh` — Pushes the current branch (unless `--no-push`), starts `test.yml` on that branch or `--ref` with `gh workflow run`, finds the run for the head SHA and waits with `gh run watch --exit-status`. Exits with the run's result (failed-log tail printed on failure), 2 on a missing or unauthenticated `gh`, bad arguments or a run it cannot find. No workflow or `package.json` script calls it; no test covers it.
- `scripts/regen-all.ts` — One entry for generated files. With no flag it runs each artifact's regenerate command (only `classify-tests.ts`, for `structural-suites.tsv`) and lists changed files; `--check` runs the freshness checks only and exits 1 when one is stale; `--goldens` also runs contract goldens (none are listed). Exits 2 on usage errors. Run by `bun run regen:all` and `check:regen-all` (in `verify`); test: `test/scripts/regen-all.test.ts`.

## Stress harness

- `scripts/stress/README.md` — Guide to `bun run test:stress` and the `stress-changed-tests` pull-request gate: local flags, the four execution profiles (`unit`, `serial`, `slow`, `e2e`), per-iteration receipts and seeds, exit codes, helper fan-in sampling, shard sizing, exemption records in open `master-red`, `flake` or `nightly-red` issues, and manual dispatch. It describes `run.ts`, `plan.ts`, `gate.ts` and `.github/workflows/stress.yml`.
- `scripts/stress/gate.ts` — Planner and reporter for the pull-request stress gate, called by `stress.yml`. `plan` lists the test files a pull request, merge group or dispatch touches (plus helper importers) and splits ten iterations each into shards under 25 minutes. `report` merges shard manifests, applies trusted exemptions and exits 1 on a failure or missing iteration. `mine-iterations <log>...` updates `iteration-weights.json`. Test: `test/scripts/stress-gate.test.ts`.
- `scripts/stress/iteration-weights.json` — Measured milliseconds for one stress iteration of three test files. `stress/plan.ts` reads it before the lane weight maps when sizing shards, and `gate.ts mine-iterations` merges new values in. Changing it only changes how stress work is packed into shards.
- `scripts/stress/plan.ts` — Planning functions shared by `run.ts` and `gate.ts`: test files and helpers changed against a merge base, the helper fan-in rule (all importers up to 25, else the helper's own tests plus 10 seeded importers), the profile by file suffix, per-iteration time estimates from the weight maps, shard packing, seeds, the reproduce line and `redact`. Pure apart from git calls; test: `test/scripts/stress-plan.test.ts`.
- `scripts/stress/run.ts` — `bun run test:stress [files] [--iterations N] [--base] [--head] [--seed] [--randomize] [--work] [--dry-run]`: runs each test file repeatedly (default 10) in its profile with a JUnit receipt per iteration; fails on a test failure, zero executed tests or a test that ran in iteration one but not later. Defaults to files changed against `origin/main`. Writes a JSON manifest. Exits 1 on failure, 2 on usage or setup errors. Test: `test/scripts/test-stress.test.ts`.

## Coverage gates and reports

- `scripts/coverage-baseline-gate.ts` — Compares a merged coverage summary (`--summary`) with the `--corpus` section (`prCorpus` or `fullCorpus`) of `scripts/coverage-baseline.json` as stored on `origin/main`. Fails on a global drop above 0.5 points, a directory drop above 1.0, or a larger never-loaded count. Report-only unless `COVERAGE_GATE_ENFORCE=1`, and for a provisional baseline or degraded summary. Exit 1 on an enforced fail, 2 on infrastructure error. `coverage-report` in `test.yml` runs it; `test/scripts/coverage-baseline-gate.test.ts` covers it.
- `scripts/coverage-baseline.json` — The committed coverage baseline: keys `provisional` (true), `prCorpus` and `fullCorpus` (both null), `watchlist` (empty list) and `note`. `scripts/coverage-baseline-gate.ts` reads it from `origin/main` and requires the working copy to exist; `scripts/render-coverage-summary.ts` reads the watchlist; `scripts/update-coverage-baseline.ts` writes it. While `provisional` is true or a section is null, the gate cannot fail a run.
- `scripts/coverage-diff-gate.ts` — Checks that lines a branch adds or changes in TypeScript files of the source directory (not tests, generated files or declarations) run in the merged test corpus: at least 80% of executable changed lines covered and no changed file without a coverage record. Takes `--summary` from `scripts/merge-lcov.ts` and `--base` (default `origin/main`). Doc-only diffs, a `[coverage-exempt:` commit marker and degraded data pass or go report-only. Exit 1 on fail only with `COVERAGE_GATE_ENFORCE=1`; 2 on infrastructure error. `test/scripts/coverage-diff-gate.test.ts` covers it.
- `scripts/coverage-gate-exemptions.txt` — Allowlist for the changed-line coverage gate: one path per line, `#` starts a comment, a trailing `/` makes a directory prefix. Listed paths are reported as `[e2e-exempt]` but not gated. The file holds only comments, so nothing is exempt. `scripts/coverage-diff-gate.ts` reads it from `origin/main`, so an edit takes effect after it merges; `test/scripts/coverage-diff-gate.test.ts` covers it.
- `scripts/merge-lcov.ts` — Merges the `lcov.info` files under its input paths into one regenerated lcov (`--out-lcov`) and a JSON summary (`--out-json`): totals, per-directory and per-file coverage, never-loaded files and per-line hits, for the source directory only. Skips malformed files and `coverage-merged` paths; checks `lane-manifest.json` files against `--manifest-expect` and `--sha` and sets `degraded` on a mismatch. Env: `COVERAGE_CORPUS`, `GENERATED_AT`. Exit 2 on usage or write errors. `test/scripts/merge-lcov.test.ts` covers it.
- `scripts/render-coverage-summary.ts` — Prints a Markdown block from the merged summary JSON (`--summary`): corpus, lane completeness, a degraded banner, total coverage, a per-directory table, the ten worst-covered files (watchlist first), the never-loaded count and, with `--structural`, the counts from `scripts/structural-suites.tsv`. Exit 2 on usage or read errors. `coverage-report` in `test.yml` appends it to the step summary; `test/scripts/render-coverage-summary.test.ts` covers it.
- `scripts/update-coverage-baseline.ts` — Rewrites one corpus section (`--corpus prCorpus` or `fullCorpus`) of the working-tree `scripts/coverage-baseline.json` from a merged summary (`--summary`): global totals, directory totals, watchlist files and the never-loaded count. `--promote` sets `provisional` to false. A change counts only after it merges, because the gate reads `origin/main`. Exit 2 on usage or read errors. No workflow runs it; `test/scripts/coverage-baseline-gate.test.ts` covers `buildCorpusSection`.

## Test helpers and preloads

- `test/helpers/cpu-time.ts` — Thread-CPU timing helpers built on `process.threadCpuUsage`: `threadCpuNow`, `spinCpuMs` (a synchronous CPU stretch), `cpuMs` and `cpuMsAsync` (CPU time of a call), and `watchLoopLag` (the most CPU the thread ran between two timer ticks; with `reportAtMs` it prints the worst stretch with Linux `schedstat` numbers). Only `test/loop-lag-cpu-clock.test.ts` uses it.
- `test/helpers/database-url-guard-preload.ts` — First preload in `bunfig.toml`. When `DATABASE_URL` or `GBRAIN_DATABASE_URL` is set and non-empty, it prints "TEST-RUN GUARD: refusing to start" and exits 1 before any test file loads; it never unsets the variable. `GBRAIN_TEST_ALLOW_DATABASE_URL=1` (exactly `1`) opts in. The runner scripts under `scripts/` unset both variables first. Covered by `test/database-url-guard-preload.test.ts`.
- `test/helpers/gbrain-home-preload.ts` — Preload that sets `GBRAIN_HOME` to a fresh `gbrain-test-home-*` directory under the OS temp dir when the variable is unset or empty, so tests never touch the operator's real config directory. A value already set is kept. `GBRAIN_DEBUG_PRELOAD=1` logs the path. The unit and slow runners unset `GBRAIN_HOME` first. Covered by `test/cli-import-no-signal-handlers.test.ts`.
- `test/helpers/git-env.ts` — `gitChildEnv(extra, source)` returns an environment copy for a git child process without Git's repository-locating variables (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the rest of `git rev-parse --local-env-vars`), its pathspec switches and all `GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n` pairs. It re-adds only the operator's `safe.directory` entries; `extra` wins. `git-hermetic-preload.ts` is the only importer.
- `test/helpers/git-fixture.test.ts` — Five tests of `makeGitFixture` on real temp repositories: a first commit with a clean tree, `reset` removes untracked files and restores tracked content, `reset` keeps HEAD, `commitAll` advances HEAD, and `commitAll` throws when nothing changed.
- `test/helpers/git-fixture.ts` — `makeGitFixture(dir)` runs `git init` in a caller-owned directory, sets `gc.auto=0`, `maintenance.auto=false` and a test identity, and makes an empty first commit. It returns `{ dir, reset(), commitAll(msg) }`: `reset` runs `git clean -ffdx` and `git reset --hard` without rewinding commits; `commitAll` stages everything and commits. Two tests use it.
- `test/helpers/git-hermetic-preload.ts` — Last preload in `bunfig.toml`. It wraps `Bun.spawn` and `Bun.spawnSync` so a child defaults to `process.env`, deletes from `process.env` every variable `gitChildEnv` drops, and appends `commit.gpgsign=false` and `tag.gpgsign=false` through `GIT_CONFIG_COUNT`/`KEY_n`/`VALUE_n` unless one of them is already set. `GBRAIN_DEBUG_PRELOAD=1` logs. No test file covers it directly.
- `test/helpers/git-publication.ts` — Git helpers for fixture repositories. `git` (sync) and `gitAsync` run `git -C <root>` and throw with the command, the exit status or signal, and stderr when git exits non-zero or ends without a status. `gitFixture`, `gitFixtureAsync` and `durableGitRepo` build temp repositories with commit hooks; only `git` and `gitAsync` are used, by `test/git-publication-helper.test.ts`.
- `test/helpers/golden.test.ts` — Three tests of the golden helpers: `stableStringify` sorts keys recursively, keeps array order, sorts Sets and renders Maps and BigInts; the timestamp, duration, path and key scrubbers and `mapStrings` rewrite volatile text; `expectNormalizerStable` passes a stable normalizer and throws on an unstable capture.
- `test/helpers/golden.ts` — `expectGolden(name, actual, normalizer)` compares key-sorted, normalized JSON with `<name>.json` in a `goldens` folder under the test fixtures directory (created on write); `GBRAIN_TEST_UPDATE_GOLDENS=1` rewrites it and a missing file fails. Also scrubbers and `expectNormalizerStable`. Only `golden.test.ts` imports it; `scripts/regen-all.ts --goldens` sets the variable (its list is empty).
- `test/helpers/hypervisor-steal.ts` — Steal guard for timing tests. `stealTicks()` reads the steal field of the aggregate `cpu` line in `/proc/stat` (null where unavailable). `measureWithoutSteal(measure, attempts = 5)` repeats a measurement until the steal counter did not move across it or the attempts run out, and returns the last value with the per-attempt steal deltas. Only `test/hypervisor-steal.test.ts` uses it.
- `test/helpers/interleaved-timing.ts` — `median(xs)` and `interleavedMedians(runs, first, second)`, which alternates one timed call of each of two async functions per round and returns the median of each, so a short stall hits one sample of each shape instead of a whole block. Only `test/interleaved-timing.test.ts` uses it.
- `test/helpers/large-worktree.ts` — Builds large git fixtures. `writeLargeWorktree(root, count)` writes `count` small Markdown notes in folders of 500 and returns the bytes; `commitFixtureRepository(root)` runs `git init`, turns off `gc.auto` and `maintenance.auto`, and commits; `largeBareRepository(dir, count)` returns a bare clone of that commit. Used by `test/git-fixture-maintenance.test.ts`.
- `test/helpers/operator-env-policy.ts` — Side-effect-free scrub policy: `STRIP_PREFIX` (`CONDUCTOR_`, `MCP_`, `OPENCLAW_`), `KEEP_EXACT` (`GBRAIN_HOME`, `GBRAIN_DATABASE_URL`, `GBRAIN_MODEL_DISCOVERY`, `GBRAIN_DEBUG_PRELOAD`), `KEEP_PREFIX` (`GBRAIN_TEST_`, `GBRAIN_CI_`, `GBRAIN_E2E_`), the old-name map `RENAMED`, and `isStripped`. Read by `operator-env-preload.ts` and `scripts/check-test-env-opt-ins.ts`; editing it changes what tests see.
- `test/helpers/operator-env-preload.ts` — Preload that runs right after the database guard. It exits 2 with a fix message when an old opt-in name from `RENAMED` (`GBRAIN_BASH32_REQUIRE`) is set, even with the scrub off.
